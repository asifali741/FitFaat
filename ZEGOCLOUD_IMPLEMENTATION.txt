FITFAAT VIDEO CALLING SYSTEM: ZEGOCLOUD TECHNICAL REPORT

This report provides a comprehensive breakdown of the ZegoCloud implementation within the FitFaat mobile application, covering architecture, file relations, and dependencies.

1. HOW ZEGOCLOUD WORKS (ARCHITECTURAL FLOW)
------------------------------------------
The implementation follows a "Room-based" architecture using the ZegoCloud UI Kit.

A. Configuration Phase:
   The app loads environment variables (APP_ID and APP_SIGN). These are processed by a central utility to ensure they are available in a Zego-compatible format (numbers vs strings).

B. Identity Mapping:
   When a user initiates a call, the system maps their internal FitFaat MongoDB ID to a ZegoCloud User ID. This ensures consistent identity across different platforms (Android/iOS).

C. Room Synchronization:
   Both the doctor and patient are directed to a Room ID (callID) derived from their shared Appointment ID. This "deterministic ID" approach eliminates the need for complex signaling; if both join the "appt_<appointment_id>" room, they are automatically connected.

D. Native Integration:
   Because ZegoCloud requires access to camera, microphone, and hardware acceleration, it uses native modules. The app is configured with MultiDex support and specific Kotlin versions to accommodate the Zego engine.

E. Runtime Execution:
   1. The user clicks a "Start Call" or "Video Icon".
   2. The app requests runtime permissions (Camera/Mic).
   3. The Zego engine initializes with the provided credentials.
   4. The UI Kit renders a full-screen, production-ready call interface.
   5. Upon hanging up, the app automatically navigates the user back to the previous context (Chat or Appointment Details).


2. FILE-BY-FILE RELATION TO ZEGOCLOUD
-------------------------------------

[CORE CONFIGURATION]
- utils/zegoConfig.ts: 
  * The "Brain" of the setup. 
  * Maps .env variables (ZEGO_APP_ID, ZEGO_APP_SIGN).
  * Provides getZegoUserID() and getCallID() helpers to ensure IDs are alphanumeric/valid for Zego.

- app.config.js:
  * Native Bridge. 
  * Configures Android permissions (CAMERA, RECORD_AUDIO, MODIFY_AUDIO_SETTINGS).
  * Sets up MultiDexEnabled=true (Zego is a large SDK).
  * Defines minSDK=21 and Kotlin=1.9.0 requirements.
  * Adds ProGuard rules to prevent the Zego SDK from being "obfuscated" or broken during build.

- package.json:
  * Defines the 4 essential Zego SDKs and their versions.

[THE CALL SCREEN]
- app/(main)/(conference)/video-call.tsx:
  * The actual "Video Room".
  * Handles runtime permission requests using PermissionsAndroid.
  * Dynamically loads the Zego Module (prevents crashing in Expo Go).
  * Renders the <ZegoUIKitPrebuiltCall /> component.

[UI TRIGGER POINTS]
- components/VideoCallButton.tsx:
  * A reusable UI component that provides the consistent camera icon styling across the app.

- components/AppointmentChat.tsx:
  * Context: Header of the chat between Doctor/Patient.
  * Relation: Imports VideoCallButton and triggers navigation to /video-call with the current appointmentId.

- app/(main)/(conference)/appointment-summary.tsx:
  * Context: Post-booking confirmation screen.
  * Relation: Provides the "Start Video Call" button once an appointmentId is generated by the server.

- app/(main)/(conference)/appointment-details.tsx:
  * Context: Appointment management list/details.
  * Relation: Syncs the "Start Call" button with a countdown timer; only enables the Zego trigger when the session is actually due.


3. ALL ZEGOCLOUD DEPENDENCIES
-----------------------------

[PRIMARY SDKs]
- @zegocloud/zego-uikit-prebuilt-call-rn: Main UI component for the video interface.
- @zegocloud/zego-uikit-rn: The underlying UI toolkit.
- zego-express-engine-reactnative: The core real-time audio/video engine.
- zego-zim-react-native: Zego In-app Messaging (handling signals and in-call chat).

[SUPPORTING LIBRARIES]
- expo-camera: Used for permission management and camera hardware interface.
- expo-build-properties: Required to inject native Gradle settings (MultiDex/minSDK) for Zego.
- react-native-safe-area-context: Ensures Zego UI elements don't overlap with device notches.
- @sayem314/react-native-keep-awake: Prevents the screen from turning off during a video consultation.


4. BUILD REQUIREMENTS (SUMMARY)
-------------------------------
For ZegoCloud to function, the app MUST be built as a "Development Build" or "Production APK". It will NOT work inside the standard "Expo Go" app from the Play Store because of these native dependencies:
- android.permission.CAMERA
- android.permission.RECORD_AUDIO
- MultiDex support enabled
- Native Zego Express Engine C++ binaries.
